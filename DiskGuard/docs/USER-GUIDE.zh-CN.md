# DiskGuard 使用与 Sandboxie 原生提示指南

> 适用范围：DiskGuard 独立控制器，Windows 10/11 x64。不要把上游 Sandboxie 的 Windows 7 支持声明当作 DiskGuard 的支持承诺。云端 Server 2022 测试不能代替客户端验收。本文是操作说明，不是某台电脑已经通过安全验收的证明。

## 1. 安装前先确认

1. 从本 Fork 的 [Releases](https://github.com/KAIKAIKAISER/Sandboxie/releases) 下载完整安装包或便携 ZIP，勿只复制 EXE。核对同一版本的 `SHA256SUMS.txt` 和 `BUILD-MANIFEST.json`：
   ```powershell
   Get-FileHash .\DiskGuard_0.2.2_x64-setup.exe -Algorithm SHA256
   ```
   把结果与校验文件逐字符比较。校验值与下载文件来自同一站点，并不能代替可信发布者签名。
2. DiskGuard 自身当前未取得发布者代码签名，可能显示“未知发布者”或 SmartScreen 提醒。不能据此宣称文件安全；来源或校验不符时停止，不要关闭 SmartScreen、驱动签名强制或安全启动。
3. 内置的是未经修改的官方 Classic 5.73.8 安装器；安装前校验固定哈希和 Authenticode。已安装的 Plus/Classic 会保留，不自动覆盖、降级或修复。
4. 准备重要文件备份。初次尝试请用测试目录，不要直接对系统盘、Windows、Program Files 或真实工作数据设置广泛黑名单。

## 2. 安装包与便携包

### 安装包

运行安装包。缺少运行时时，安装流程会通过标准 Windows UAC 请求权限部署官方驱动和服务。授权拒绝后，DiskGuard 文件可能已安装，但保护尚未就绪；可打开应用重试。需要重启时先保存工作，按实际提示重启。

### 便携包

解压整个 ZIP，保留 `runtime/`。打开 DiskGuard，点击“安装内置运行时”。“便携”仅指界面可解压运行，不代表驱动、服务可以免安装或免管理员权限。系统还需 WebView2；安装包可按需下载引导安装器，缺少 WebView2 的离线环境应先按微软官方方式部署。

### 三种状态必须区分

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| 驱动与服务已连接 | 运行时可用，不等于某个应用规则已应用 | 为目标应用保存并应用策略 |
| 策略已写入 | 记录的配置已写入和回验，不是不可绕过的持续证明 | 确认自动保护、重新启动应用并验证行为 |
| 监控未就绪 | 没有可用日志会话，或其他监控器占用共享队列 | 排查会话代理；不要把无日志当作无访问 |

## 3. 第一次保护 QQ、微信或其他 EXE

1. 正常退出目标程序及其后台进程。已在沙箱外运行的进程不能事后迁移到沙箱；仅关闭主窗口可能不够。
2. 在“应用管理”选择预设的实际 EXE，或添加应用。不要猜测商店版、安装版、不同渠道的可执行文件路径。
3. 先用“只监控”或少量黑名单验证兼容性。只监控仍具有 Sandboxie 的基础隔离和写入重定向，不等于完全不改变应用环境。
4. 添加需要保护的目录，并保留“递归”。关闭递归只匹配目录对象自身，不能保证通过已知完整路径打开子文件会被阻止。
5. 点击“保存并应用策略”。普通“保存”只保存配置；修改后的规则尚需应用。
6. 如需从原快捷方式启动也自动入箱，启用“自动保护此应用”并重新应用。全局禁用强制规则时自动保护失效，不能忽略提示。
7. 点击“沙箱启动”，用无敏感内容的测试文件验证：目标目录不能打开/读取、相邻允许目录仍能使用、子进程仍在同一沙箱。不能只凭绿色状态判定成功。

**默认项有区别：**首次启动的 QQ/微信预设是停用的黑名单配置；新添加应用默认只监控且自动保护关闭。检查当前选项，不要假设添加即保护。

### 白名单的限制

白名单需要 Sandboxie 相应安全功能授权；无授权时拒绝应用。即使有证书，全局规则或模板中的磁盘放行例外也可能使白名单拒绝应用。程序不会自动改写共享模板。系统、Program Files、Sandboxie 与目标程序目录是已说明的兼容例外，写入仍重定向到沙箱。不要把它理解成只允许访问你手选的几个目录。

## 4. Sandboxie 原生界面、托盘和提示

DiskGuard 不依赖 SandMan 的 Qt 界面，但官方 Classic 运行时可能自动启动签名的 `SbieCtrl.exe`（MFC 会话代理）。因此出现 Sandboxie 原生托盘、黄色边框、消息窗口或“在沙箱中运行”入口，不一定是安装重复或 DiskGuard 出错。

- **原生会话代理：**日志依赖可信会话。DiskGuard 不伪装、接管或绕过它的签名检查。没有日志会话时，磁盘策略可以仍然有效，但日志不就绪。
- **黄色边框 / 沙箱名称：**是原生界面提示，不替代进程归属和访问行为测试；显示方式取决于原生设置。
- **文件恢复提示：**Sandboxie 默认把应用写入重定向到沙箱。恢复会把沙箱文件复制回真实位置，应人工确认来源、内容和目的地。不要为减少提示而随意开放宿主写穿。
- **删除沙箱内容：**可能删除下载、聊天缓存或其他尚未恢复的文件。DiskGuard 移除应用不等于删除沙箱内容；不要把“删除内容”作为修复连接问题的通用步骤。
- **试用/证书提示：**按官方运行时及其授权规则处理。DiskGuard 不提供证书、不绕过授权；是否影响当前模式以实际能力门禁和原生消息为准。
- **监控竞争：**同一 Windows 会话共享监控流。SandMan 或其他工具开启资源监控时，请先关闭其监控，再使用 DiskGuard 日志；不要让多个工具争抢后误认日志完整。

### 常见 SBIE 消息速查

以下编号与英文含义核对自仓库 `Sandboxie/msgs/Sbie-English-1033.txt`。安装的其他版本可能不同，始终保留**完整编号、程序/服务名、括号内错误码、系统构建和消息全文**。本表不是实时告警列表。

| 编号 | 原生含义 | 建议 |
| --- | --- | --- |
| SBIE1101 | 驱动初始化完成 | 正常信息；仍需确认服务和具体应用策略 |
| SBIE1103 / SBIE9153 | 驱动未能启动 | 检查官方签名、完整安装、重启要求和系统事件；不要关闭签名强制 |
| SBIE1105 | 未知操作系统版本 | 核对系统构建与官方运行时兼容性，不要隐藏警告继续当作已保护 |
| SBIE1301 | 程序在沙箱外启动 | 退出后台实例，核对真实 EXE、强制规则和全局禁用状态 |
| SBIE1307 | 程序受到网络限制 | 检查网络策略；不是磁盘目录黑名单提示 |
| SBIE1308 | 程序受到启动限制 | 检查启动/运行限制及程序路径 |
| SBIE2102 | 文件过大，不能复制到沙箱 | 检查迁移限制，先备份；勿直接改为宿主写穿 |
| SBIE2203 | 与 Sandboxie 服务通信失败 | 检查 SbieSvc、安装与重启状态；连接失败不能算已保护 |
| SBIE2204 | 沙箱内服务不能启动 | 记录服务名和错误码；如 RpcSs，结合具体运行时/系统版本排查 |
| SBIE2335 | 进程初始化失败 | 保留完整消息，核对应用架构、系统和运行时兼容性 |
| SBIE2338 | 进程架构不受支持 | 核对实际 EXE 架构；DiskGuard 当前仅承诺 x64 目标范围 |
| SBIE9154 | 驱动与服务版本不同 | 完成重启或以同一官方包修复，不要混换组件 |
| SBIE9156 | 驱动初始化未完成 | 检查安装、系统事件和重启要求 |

遇到不在表内的消息，先在原生消息窗口查看详情，再查对应版本的官方文档。不要通过全局隐藏消息、禁用隔离或删除数据来“解决”未知错误。

## 5. 访问日志的正确理解

- “文件打开”“策略检查”不是读取了文件字节的证明；无法确认的结果保持“未确认”。
- 当前不提供完整的目录枚举或实际读取审计。短命进程结束后可能无法可靠归属，不会猜测应用身份。
- 日志只在本 UI 运行且监控连接时采集，最多保留 10,000 条；退出期间不采集，旧事件可能被移除，不是无损审计。
- 页面显示最近 200 条，CSV 导出包含当时内存中的全部筛选结果，不包含已经丢失的事件。
- 导出路径、进程名和 PID 可能包含隐私。对外提交前人工脱敏；不要公开真实私人文件路径。

## 6. 配置只读、未完成保存和恢复

配置位于界面错误提示显示的应用配置目录（Windows 通常是 `%APPDATA%\io.diskguard.desktop`，以实际显示为准）。运行时安装回执另存于 `%LOCALAPPDATA%\DiskGuard\runtime-install.json`。

| 文件 | 用途 |
| --- | --- |
| `config.json` | 当前应用及规则配置 |
| `applied.json` | 上次写入的策略快照，不是运行时永远未变的证明 |
| `pending-save.json` | 跨本地文件与运行时策略的未完成保存日志 |
| `config.last-good.json` / `applied.last-good.json` | 上次开始保存前的有效状态 |

1. 出现“保存未完成”时，部分停用/删除策略可能已经生效；不要继续依赖旧的绿色状态。先退出受控应用，备份整个配置目录和必要的沙箱数据。
2. 修复磁盘空间、目录写权限、服务连接问题，点击“恢复保存 / 重新载入”。程序会继续完成**同一次保存**，不是回滚；再次移除已删除的专用策略是幂等操作。
3. 如果只有 JSON 损坏，程序保留原文件并只读启动。先关闭 DiskGuard，保留副本，检查编码和 JSON；确认没有未完成日志后，才可由有经验的用户恢复成对的 last-good 文件，再打开并重新应用、验证。
4. `pending-save.json` 本身损坏时不要直接删除，程序无法证明已完成哪些运行时操作。联系维护者并同时核对 `Sandboxie.ini` 中对应 `DiskGuard_` 节；配置含隐私，勿直接公开。
5. 手工恢复本地文件不会自动恢复或撤销真实运行时策略。必须对照运行时配置、重新应用并实测；不要删除共享 Sandboxie 配置、驱动或沙箱数据。

## 7. 暂停、更新和卸载

- 停用/删除应用前退出对应沙箱进程，再保存。沙箱文件保留，避免误删用户数据。
- 更新目标软件改变 EXE 路径后，需要在 DiskGuard 更新路径并应用；检查更新器和新子进程的实际归属。
- UI 退出后已应用强制规则继续生效，但停止日志采集。
- 卸载 DiskGuard 不会删除共享官方运行时和沙箱数据。卸载前如不希望继续强制入箱，应先停用受控应用并保存；若 UI 已卸载，可通过官方 Sandboxie 管理工具核对相应 `DiskGuard_` 沙箱，先备份再操作。

## 8. 反馈时提供什么

提供 DiskGuard 版本/构建提交、Windows 版本及构建号、运行时版本、应用版本、实际操作顺序、完整 SBIE 编号/错误码、脱敏日志和是否可复现。安装失败提供脱敏后的 `runtime-install.json`。不要上传证书私钥、密码、原始聊天文件或整个私人目录。

发布验收与维护者操作见 [RELEASE-CHECKLIST.zh-CN.md](RELEASE-CHECKLIST.zh-CN.md)；详细测试边界见 [VALIDATION.md](VALIDATION.md)。
